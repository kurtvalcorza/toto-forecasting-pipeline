## Conformance notes

_Requirement identifiers in these notes (for example `ST1`, `PAR3`, `DAT24`, `EVAL21`) are the NOTEBOOK_SPEC 1.1 numbering they were written against; NOTEBOOK_SPEC 2.0 renumbered its sections and the pull request that migrated this repository reports conformance against the 2.0 pre-flight checklist (§26) and report format (§30)._

- **Standalone carrier and isolated environment (ST1–ST6, RUN1, RUN10, ENV6):** the primary path performs no clone, repository install or repository import, and installs nothing into the notebook kernel. Section 2 writes the package's 4 modules, the stage runner, the hash lock compiled from the `pyproject.toml` pins (`uv pip compile pyproject.toml --python-version 3.12 --python-platform x86_64-manylinux_2_28 --generate-hashes --only-binary :all:`), the 3-file snapshot manifest and `LICENSE` into a run directory and verifies each against its SHA-256; a pinned `uv` wheel builds a managed CPython 3.12.12 environment from the lock with `--require-hashes`, reused per lock digest, and every learner cell runs one stage in its own process (`MPLBACKEND=Agg`, no inherited `PYTHONPATH`/`PYTHONHOME`/`PYTHONSTARTUP`). `metadata.dimer.generated_from` records the repository, the generating revision, the package SHA-256, the carried-file digests and the generator version.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when a carried file differs from the repository, when the lock does not pin every runtime pin with hashes, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition:** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries that are absent (`README.md`, `config.json`, the 9.8 GB `model.safetensors`), from the Hugging Face Hub at the immutable revision (never `main`); `verify_snapshot` re-hashes every entry; `from_pretrained(weights_dir=...)` (CUDA when present) hands the verified directory to `Toto2Model.from_pretrained`, which builds the model from that directory's `config.json` and loads the SafeTensors file from it. The manifest's `model.safetensors` digest comes from the Hub's LFS metadata at the pinned revision (the checkpoint is not kept in this repository); `verify_snapshot` over the real file passed in the 2026-09-14 Kaggle T4 run of the previous notebook (3 files verified) — see `../docs/release-verification.md`.
- **Role stages:** `validate_inputs` (DAT24) writes `outputs/toto_forecasting_input_manifest.json` with the schema, ceilings (`MIN_CONTEXT`, `MAX_CONTEXT`, `MAX_HORIZON`), per-variate observations, verdict, and one recorded rejection finding (a too-short context); the two patch-size rules are model-dependent and stay in `forecast`, as the manifest's schema states. `evaluation_report` (EVAL21) writes `outputs/toto_forecasting_evaluation_report.json` — `sample-sanity` with `mae`, `rmse`, `interval_coverage` (q10–q90) and the `last_value_baseline` on the chronologically withheld truth, `not-measurable` (with what would make the task measurable) when no truth is supplied.
- The default sample is the same deterministic two-variate synthetic series (seed 11, 320 steps, horizon 48) as the previous notebook, generated in code; its metrics are sanity evidence for the input contract, the holdout plumbing and the forward pass, not a correctness or benchmark claim.
- Forecasting obligations (Notebook Specification §20.3): chronological order is preserved, the final horizon is withheld, no future target reaches the model, horizon and effective context (including the mask-aware left padding to a patch multiple) are printed, q=0.5 is stated to be a model median, the other quantiles are described as model quantiles rather than confidence intervals, and the last-value baseline, a seasonal-naive forecast and a least-squares trend + season reference are compared on the same holdout; on the synthetic series the noise floor is printed too, and the notebook says that the informed trend + season fit sits closer to it than the model.
- The 2.5B checkpoint is loaded in its stored precision; `from_pretrained(device='cuda', ...)` raises a typed error when no CUDA device is present because the CPU path is not the supported release-reference path.
- BYOD CSV headers are inspected before pandas ingestion so duplicate columns cannot be silently renamed; the delimiter is detected; text values in a target column are refused naming the column; empty values are refused with their line numbers; timestamps must parse and be unique, increasing and regularly spaced, and they are kept in the exported CSV with the last context timestamp and the spacing in the result JSON; a series longer than `MAX_CONTEXT + HORIZON` keeps its most recent rows and the trim is reported. `BYOD_CSV_PATH` works in any runtime and the Colab upload is guarded. `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the
  clean-runtime execution requirement; a release review must confirm that a recorded clean run in
  `docs/release-verification.md` matches the notebook revision under review before the status is
  promoted to `Release-grade`.
